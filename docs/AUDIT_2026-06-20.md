**Auditor pass:** 2026-06-20 · **Repo HEAD:** `3ea7441` ("feat(release): Nexus v1.0 - 171ms TTFT Hybrid Routing Engine")
**Environment available to auditor:** Linux sandbox, no model weights, macOS/Metal-built C++ extension, `llama_cpp` not importable → **benchmark regeneration is BLOCKED** (see §12, §20).

## 1. Executive Verdict

The Nexus codebase is, at the implementation level, **substantially more honest than its number-reporting layer**. Nearly every architectural claim audited (dual-path gate, `MAX_SPLICE_POS=256`, 5% suffix recompute, `force_tool_id` bypass, L0/FSM separation, `.atb` ABI, page alignment, hazard pointers, calibration constants) is **verifiable to concrete symbols in source**. The negative results (RoPE boundary, blockmask, ColBERT) are real and well-supported.

The quantitative layer is **not clean**. The central defect is **two complete, conflicting benchmark runs committed at two different commits**, and a documentation set that **cites the files of one run while printing the numbers of the other**:

| | Older run (`results/*.json`, commit `1384a33b`) | Newer run (`docs/paper/data/`, HEAD `3ea7441`) |
|---|---|---|
| Gateway TTFT P50 | **171.3 ms** | **237.4 ms** |
| Gateway accuracy | **0.91** | **0.89** |
| B3 / B_RP TTFT P50 | **1.33 s** | **1.50 s** (1498.6 ms) |
| B1 / B_FC TTFT P50 | **9.48 s** | **12.35 s** |
| L0 hit rate | **66%** (n=1 seed) | **69.5%** (mean of 10 seeds) |

Both runs are real and traceable. They differ on the headline by **+38.6%** (171→237 ms) — on nominally identical hardware/model, hours apart. **No third run exists to break the tie, and I cannot reproduce either.** Therefore:

- `README.md`, `RELEASE_V1.md`, `docs/architecture.md`, `docs/internals.md` print the **paper run's** numbers (237.4 ms / 0.89 / 1.50 s / 12.35 s) but **cite the `results/` files**, which contain the **older run's** numbers (171 ms / 0.91 / 1.33 s / 9.48 s). `results/README.md` correctly reports the `results/` files (171 ms / 0.91 / 1.33 s / 9.48 s) — and therefore **directly contradicts `README.md` while citing the same filenames.** This is the single most damaging integrity problem and is true regardless of which run is "right."
- The headline "**237.4 ms**" to 0.1 ms precision (and `verify_paper_math.py`'s 237.39345849 ms to 8 decimals) is **false precision**: a metric that moves 38.6% between two runs cannot be reported to four significant figures.
- The paper carries **two different production TTFT P50 values** — **237.4 ms** (gateway harness, `gateway_full.json`) and **307.9 ms** (ablation harness, `ml_ablation_table.csv`) — for the *same* config (P20, 20% CE). `main.tex:459` acknowledges this in passing; a reader will trip on it.
- "**Equivalent accuracy / without loss in routing fidelity**" is an **overstatement**. Nexus 0.89 vs B_RP 0.92 is a **3-point nominal accuracy drop**. It is defensible only as "within overlapping 95% CIs," not as "equivalent" or "no loss."
- "**Nexus eliminates this [prefill] wall entirely**" (`main.tex:164`) is **contradicted by the design**: Path B (P>256) does **text prefill** — the wall is bypassed for P≤256, not eliminated.
- The **RoPE physics-boundary table** (`physics_boundary_rope.csv`) — one of the paper's best contributions — is labeled *"Data sourced from architectural validation records prior to V1.0 codebase freeze."* It has **no runnable regeneration path** in the frozen repo.

**Recommended posture:** honest **systems-prototype / negative-results-forward** paper. The engineering is real; the headline numbers must be (a) reconciled to a single regenerated run, (b) de-precisioned, and (c) stripped of "eliminates/equivalent/strictly dominates" rhetoric. **Do not edit manuscript numbers until the canonical run is regenerated or the user designates one** (see §20 decision).

## 8. Codebase Claim Audit Report (summary)

The implementation is real and well-structured. **No fabricated mechanisms found.** All ten "core" architectural claims map to concrete symbols (§6). The three claims requiring softening are wording, not fabrication:

1. **"Zero-copy / UMA DMA"** — exists only as a telemetry `cout` and a header comment. The splice path performs an `llama_kv_cache_seq_cp` (a copy) plus a tail recompute through `llama_batch`. Recommend: drop "zero-copy"; keep "warm copy" and "zero dynamic heap allocation on the C++ hot path."
2. **"Eliminates the prefill wall entirely"** — design contradicts it (Path B text-prefills). Recommend: "bypasses the prefill wall for P≤256; falls back to warm-copy or text prefill beyond."
3. **"Production gateway"** — a genuine FastAPI/uvicorn OpenAI-compatible server exists, but it is a single-host research prototype. Recommend: "prototype gateway."

The **L0-vs-FSM separation** the project rules care about is correctly maintained in code (two `RadixNode` definitions, two files, two arenas). The **`force_tool_id`** anti-double-routing mechanism is exactly as documented.
