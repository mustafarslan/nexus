The Model Context Protocol (MCP) enables Large Language Models (LLMs) to dynamically execute external tools by prepending function and parameter descriptions to the context window. However, in multi-tenant agentic workflows with extensive tool registries, injecting these schemas introduces severe computational overhead. Ap\-pend\-ing all schemas to the context window imposes a prefill compute bottleneck that scales quadratically with sequence length ($\mathcal{O}(P^2)$) self-attention operations, whereas selective retrieval requires a retrieve-and-prefill cycle on every turn, invalidating the cached Key-Value (KV) representations of downstream conversation history.

We present \textsc{Nexus}, a zero-allocation context routing and memory management system that bypasses the tool schema prefill wall. \textsc{Nexus} decouples tool definitions from runtime prefill compute by framing schemas as independent, offline-compiled KV cache blocks (\texttt{.atb}) that are spliced directly into active mid-conversation contexts. The system comprises three coordinated layers: (1) an L1 Semantic Lookaside Buffer (SLB) that performs microsecond-scale ($\approx 4.19\,\mu\text{s}$), SIMD-accelerated linear sweeps over registered tool embeddings; (2) a Left-Child Right-Sibling (LCRS) radix trie finite-state machine (FSM) that constrains generated logits to valid routing vocabulary; and (3) a stride-aware KV cache splicer that maps and blits pre-compiled KV blocks via user-space Direct I/O and applies YaRN relative position corrections.

We evaluate \textsc{Nexus} using Qwen2.5-14B-Instruct on Apple Silicon (Darwin arm64) unified memory. \textsc{Nexus} achieves a gateway routing+splice latency P50 of $\approx 160\,\text{ms}$ (regenerated 2026-06-20; this routing metric excludes first-token generation and is not TTFT) at $89.0\%$ tool-routing accuracy. Measured like-for-like, end-to-end TTFT is $\approx 2.34\times$ faster than the retrieve-and-prefill baseline ($B_{RP}$), with a $\approx 3$-point accuracy trade-off (0.89 vs.\ 0.92).
