\section{Background and Motivation}
\label{sec:background}

This section formalizes the computational complexity of the prefill phase in Transformer-based architectures and details the mathematical mechanisms of Rotary Position Embeddings (RoPE) that constrain dynamic KV cache manipulation.

\subsection{The Prefill Wall in Agentic Serving}
In a standard Transformer layer, the self-attention mechanism computes Query ($Q$), Key ($K$), and Value ($V$) projections from an input sequence of tokens. For an input context of length $n$, the attention matrix computation is defined as:
\begin{equation}
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_{head}}}\right)V
\end{equation}
where $d_{head}$ represents the hidden dimension per head. Computing the product $Q K^T$ requires calculating pairwise inner products across all positions in the sequence. During the prefill phase, all $n$ tokens are processed simultaneously, requiring $\mathcal{O}(n^2 \cdot d_{head} \cdot L)$ floating-point operations across $L$ layers.

In multi-tenant agentic applications, the server maintains an active history of the user conversation, denoted by sequence length $H$. When a user query requires the inspection of $M$ tools, each represented by a schema description of length $S$, the system has two straightforward choices:
\begin{enumerate}
  \item \textbf{Full-Context Concatenation ($B_{FC}$):} Append all $M$ tool schemas to the conversation history. The input context length grows to $n = H + M \cdot S$. The prefill complexity scales quadratically as $\mathcal{O}((H + M \cdot S)^2 \cdot d_{head} \cdot L)$, leading to excessive latencies.
  \item \textbf{Standard Retrieve-and-Prefill ($B_{RP}$):} Use a semantic searcher to identify the top-$K$ most relevant tools, then append only those $K$ schemas. The context size becomes $n = H + K \cdot S$. While $K \ll M$ reduces the attention footprint, the system must still compute the prefill over the $K$ retrieved schemas ($K \cdot S$ tokens) on every single turn.
\end{enumerate}

Both approaches execute the underlying quadratic prefill compute online, introducing latency. To bypass this, we must compile the KV caches of tool schemas offline and splice them into memory without online prefill.

\subsection{Rotary Position Embeddings and Phase Error}
Modern LLMs (e.g., Llama, Qwen) utilize Rotary Position Embeddings (RoPE)~\cite{peng2023yarn} to encode positional information. RoPE applies a rotation matrix to the Query and Key projection vectors at each position. Let $\mathbf{k}_m \in \mathbb{R}^{d_{head}}$ be the key vector at position $m$. The rotated key $\mathbf{k}'_m$ is computed as:
\begin{equation}
\mathbf{k}'_m = \mathbf{R}_{\Theta, m} \, \mathbf{k}_m
\end{equation}
where $\mathbf{R}_{\Theta, m}$ is a block-diagonal rotation matrix defined by rotary frequencies $\theta_i = \text{base}^{-2i/d_{head}}$:
\begin{equation}
\mathbf{R}_{\Theta, m} = \text{diag}\left( \mathbf{R}_m^{(1)}, \mathbf{R}_m^{(2)}, \dots, \mathbf{R}_m^{(d_{head}/2)} \right)
\end{equation}
with $2 \times 2$ rotation blocks:
\begin{equation}
\mathbf{R}_m^{(i)} = \begin{pmatrix} \cos(m \theta_i) & -\sin(m \theta_i) \\ \sin(m \theta_i) & \cos(m \theta_i) \end{pmatrix}.
\end{equation}
For our validation anchor (Qwen 2.5-14B), the frequency base is set to $\text{base} = 1,000,000$.

When a tool schema is compiled offline, its KV cache is generated starting at a base position $m_0$ (typically $m_0 = 0$). Suppose this pre-compiled KV block is spliced into an active conversational context at a downstream position $n_{\text{past}}$. If the cache is spliced directly without adjusting the rotary embeddings, the attention calculation evaluates the query at position $n_{\text{past}} + j$ against the key compiled at position $m_0 + j$.

The dot product between query $\mathbf{q}_n$ and key $\mathbf{k}_m$ under RoPE depends strictly on their relative distance:
\begin{equation}
(\mathbf{R}_{\Theta, n} \mathbf{q})^T (\mathbf{R}_{\Theta, m} \mathbf{k}) = \mathbf{q}^T \mathbf{R}_{\Theta, m - n} \mathbf{k}.
\end{equation}
If we splice the pre-compiled block compiled at $m_0$ into the active context at $n_{\text{past}}$, the relative offset is corrupted. The query at position $n \ge n_{\text{past}}$ expects to attend to key at position $m = n_{\text{past}} + j$. However, the key vector possesses the rotation of position $m_0 + j$. The resulting phase error $\Delta \theta_i$ for frequency component $i$ is:
\begin{equation}
\Delta \theta_i = (n_{\text{past}} - m_0) \cdot \theta_i.
\end{equation}

For high-frequency dimensions (small $i$), the rotary frequency $\theta_i$ is large, meaning even minor positional shifts $(n_{\text{past}} - m_0)$ produce rapid rotation changes, causing severe phase drift. This phase mismatch distorts the attention dot products, leading to a degradation in the softmax probability distribution. To prevent this, the cache splicer must dynamically shift the position of the pre-compiled keys using trigonometric rotations. 

Furthermore, as context depth $n_{\text{past}}$ increases, the absolute positional index scale changes, triggering scale-dependent frequency interpolations (e.g., YaRN scaling). This limits the depth at which splicing remains mathematically viable without full context recomputation, defining the RoPE phase-drift constraints.
